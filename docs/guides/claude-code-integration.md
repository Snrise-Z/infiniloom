# Using Infiniloom with Claude Code

This guide covers practical workflows for combining Infiniloom with [Claude Code](https://docs.anthropic.com/en/docs/claude-code), Anthropic's CLI coding assistant. Infiniloom generates structured, security-scanned context that helps Claude Code give more accurate, relevant answers about your codebase.

## Why Use Infiniloom with Claude Code?

Claude Code can read files directly, but Infiniloom adds value in several key scenarios:

| Scenario | Without Infiniloom | With Infiniloom |
|----------|-------------------|-----------------|
| **Large codebase** | Claude Code reads files one at a time; may miss important context | Single command generates ranked, structured overview |
| **Code review** | Must manually identify which files are affected by a change | `infiniloom diff` automatically finds changed files + their callers/callees |
| **Security** | Risk of pasting API keys, tokens, or credentials into Claude | Automatic secret detection and redaction |
| **Onboarding** | Takes many read operations to understand project structure | `infiniloom map` provides a ranked symbol overview instantly |
| **Blast radius** | Must manually trace dependencies before refactoring | `infiniloom impact` shows all dependents |

## Workflow 1: Enrich CLAUDE.md with Architecture Context

Add a project architecture overview to your `CLAUDE.md` so Claude Code has structural awareness from the start of every session.

```bash
# Generate a ranked symbol map (top functions, classes, types)
infiniloom map . --budget 3000 > /tmp/symbols.txt

# View the output, then paste the relevant parts into your CLAUDE.md
cat /tmp/symbols.txt
```

Add to your `CLAUDE.md`:

```markdown
## Architecture Overview

Key symbols ranked by importance (generated by `infiniloom map`):

[paste symbol map here]
```

You can also add project statistics:

```bash
infiniloom scan . --json | python3 -c "
import json, sys
d = json.load(sys.stdin)
print(f'Files: {d[\"total_files\"]}, Languages: {\", \".join(d[\"languages\"].keys())}')
print(f'Total tokens (Claude): {d[\"total_tokens\"][\"claude\"]:,}')
"
```

## Workflow 2: Code Review with `infiniloom diff`

Before asking Claude Code to review a PR or branch, generate focused context that includes the changed files and their dependencies.

```bash
# Step 1: Build symbol index (one-time or after major changes)
infiniloom index .

# Step 2: Generate review context for your branch
infiniloom diff main..feature/auth-refactor \
  --include-diff \
  --depth 2 \
  --budget 100000 \
  --redact-secrets \
  -o review-context.xml
```

Then in your Claude Code session:

```
Read review-context.xml and review these changes for:
1. Security vulnerabilities
2. Bugs and edge cases
3. Missing test coverage
4. Performance issues
```

**What `--depth 2` includes:**
- **Level 1**: The changed files themselves
- **Level 2**: Direct callers and callees of changed symbols, plus related test files

## Workflow 3: Impact Analysis Before Refactoring

Before asking Claude Code to refactor a file, check the blast radius:

```bash
# Build index if not already done
infiniloom index .

# Check what depends on the file you want to change
infiniloom impact . src/auth.rs --depth 2
```

If the output shows HIGH or CRITICAL impact (10+ dependents), tell Claude Code to take a more careful, incremental approach:

```
Based on the impact analysis showing 15 dependents of src/auth.rs,
help me refactor the authenticate() function. Make the change
backward-compatible to avoid breaking callers.
```

For full call graph analysis:

```bash
infiniloom impact . src/auth.rs --call-graph --json > /tmp/impact.json
```

## Workflow 4: Full Codebase Context

For deep architectural questions, generate a complete context package:

```bash
infiniloom pack . \
  -f xml \
  --compression balanced \
  --max-tokens 150000 \
  --redact-secrets \
  -o codebase-context.xml
```

Then ask Claude Code:

```
Read codebase-context.xml. Based on this full project context:
- How does the authentication flow work end-to-end?
- What are the main entry points for the API?
- Where are the database queries concentrated?
```

**Format note**: XML format (`-f xml`) is optimized for Claude. It uses structured tags that Claude parses more accurately than plain text.

## Workflow 5: Security-Safe Context Sharing

Always use `--redact-secrets` when generating context that will be shared with any AI:

```bash
# Scan for secrets first (reports without modifying)
infiniloom pack . --security-check

# Generate context with secrets automatically redacted
infiniloom pack . --redact-secrets -f xml -o safe-context.xml
```

Infiniloom detects 15+ secret patterns including:
- AWS keys (`AKIA...`)
- GitHub tokens (`ghp_...`, `github_pat_...`)
- Private keys (RSA, EC, DSA, OpenSSH, PGP)
- API keys (OpenAI, Anthropic, Stripe, etc.)
- Database connection strings
- GCP, Azure, and HuggingFace tokens

## Workflow 6: Onboarding to a New Codebase

When you're new to a project and want Claude Code to help you understand it:

```bash
# Step 1: Get a bird's-eye view
infiniloom scan . -v

# Step 2: See the most important symbols
infiniloom map . --budget 5000

# Step 3: Generate full context for Claude
infiniloom pack . -f xml --compression balanced -o overview.xml
```

Then ask Claude Code:

```
Read overview.xml. I'm new to this project. Give me:
1. A high-level architecture summary
2. The main data flows
3. Key entry points
4. Which files I should read first to understand the core logic
```

## Workflow 7: Using the Symbol Index

The `infiniloom index` command builds a persistent symbol index that powers fast `diff` and `impact` queries. Think of it as a pre-built map of your codebase's structure and relationships.

```bash
# Build the index (stored in .infiniloom/ directory)
infiniloom index .

# Check index status
infiniloom index --status

# Force rebuild after major refactoring
infiniloom index --force

# Watch mode: auto-rebuild on file changes
infiniloom index --watch
```

**When to rebuild:**
- After pulling major changes from upstream
- After large-scale refactoring
- If `diff` or `impact` commands show stale results

**Best practice**: Add `infiniloom index` to your git post-merge hook:

```bash
# .git/hooks/post-merge
#!/bin/bash
infiniloom index .
```

## Workflow 8: Configuration for Teams

Create an `.infiniloom.yaml` configuration file so the whole team uses consistent settings:

```bash
# Generate a config file
infiniloom init

# Or use a language-specific template
infiniloom init --template rust
infiniloom init --template python
infiniloom init --template typescript
```

Example `.infiniloom.yaml` for a team using Claude Code:

```yaml
output:
  format: xml           # Optimized for Claude
  model: claude
  compression: balanced
  token_budget: 150000

scan:
  include:
    - "src/**"
    - "lib/**"
  exclude:
    - "tests/*"
    - "docs/*"
    - "*.generated.*"

security:
  scan_secrets: true
  redact_secrets: true
  allowlist:
    - "EXAMPLE"
    - "test_key"
```

Configuration precedence (later overrides earlier):
1. Default values
2. Config file (`.infiniloom.yaml` / `.infiniloom.toml` / `.infiniloom.json`)
3. Environment variables (e.g., `INFINILOOM_OUTPUT__MODEL=claude`)
4. CLI flags

See [Configuration Guide](../CONFIGURATION.md) for full reference.

## Shell Aliases

Add these to your `.zshrc` or `.bashrc` for quick access:

```bash
# Quick review context for current branch
alias il-review='infiniloom index . && infiniloom diff --staged --include-diff --depth 2 --redact-secrets'

# Full project context for Claude
alias il-context='infiniloom pack . -f xml --compression balanced --redact-secrets'

# Symbol overview
alias il-map='infiniloom map . --budget 3000'

# Quick project stats
alias il-stats='infiniloom scan . -v'

# Impact check before editing a file
il-impact() { infiniloom index . && infiniloom impact . "$1" --depth 2; }
```

## Using the Python Binding with Claude SDK

Instead of CLI commands, you can use the Python binding directly with the Anthropic SDK for programmatic workflows:

```python
import infiniloom
from anthropic import Anthropic

# Pack with the binding — no subprocess, native Rust speed
context = infiniloom.pack(".", format="xml", model="claude", compression="balanced")

# Send to Claude API
client = Anthropic()
response = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=4096,
    messages=[{"role": "user", "content": f"{context}\n\nReview this codebase for security issues."}]
)

# Impact analysis via binding
infiniloom.build_index(".")
impact = infiniloom.analyze_impact(".", ["src/auth.py"])
print(f"Impact: {impact['impact_level']} — {impact['summary']}")

# Diff context via binding
diff = infiniloom.get_diff_context(".", from_ref="main", to_ref="HEAD", include_diff=True)
print(f"Changed {len(diff['changed_files'])} files, {len(diff['context_symbols'])} related symbols")

# Embedding chunks for RAG
chunks = infiniloom.embed(".", max_tokens=1000)
```

Install: `pip install infiniloom anthropic`

## Tips

1. **Use XML format for Claude** - Claude processes structured XML more accurately than plain text or Markdown.
2. **Always redact secrets** - Make `--redact-secrets` a habit, or set it in your config file.
3. **Rebuild index after big changes** - The symbol index needs refreshing after major refactors or pulls.
4. **Use token budgets** - Set `--max-tokens` to stay within Claude's context window. For Claude Opus/Sonnet with 200K context, a budget of 150K leaves room for conversation.
5. **Depth 2 for reviews** - `--depth 2` on the diff command gives the sweet spot of changed files plus their immediate dependencies.
